
# EcoNexus AI

**AI-powered environmental intelligence and dust-control platform for large construction sites.**

EcoNexus AI forecasts PM10 and PM2.5 concentrations from 15 minutes to 72 hours ahead using XGBoost, explains forecast drivers using exact Shapley attribution and a receptor model, and uses its **DUSTWISE** engine to rank hotspots and coordinate water tankers and sweepers.

The platform also verifies whether interventions worked by comparing observed outcomes against a no-action forecast, then learns from verified results. The integrated **EcoNexus Copilot** answers site-related questions using the same platform data.

**Technology Stack:** Flask, XGBoost, scikit-learn, SciPy, pandas, and a dependency-free JavaScript dashboard.

> **Research and educational use only.**

## Platform Workflow

```text
OBSERVE → UNDERSTAND → PREDICT → DIAGNOSE → PRIORITIZE → OPTIMIZE → ACT → VERIFY → LEARN
```

> **Data Transparency:** This build uses synthetic data for a fictional 100-acre site named Green Valley Township. The data is generated by a physics-motivated simulator. Every value displayed in the application and reported in this README is computed by the project code. Nothing is manually entered. See [DATA_TRANSPARENCY.md](DATA_TRANSPARENCY.md).

## Objectives

- Forecast zone-level dust concentrations with measured 90% uncertainty intervals, helping site teams act before pollution levels peak.
- Convert forecasts into actionable recommendations: identify the priority zone, suggested action, required unit, and rationale. Every recommendation requires operator approval.
- Verify interventions against the counterfactual scenario of what would have happened without action, then use the results to improve future recommendations.
- Make the platform accessible to non-specialists through plain-language answers, AI-generated shift briefings, a command palette, and an assistant restricted to platform data.

## Installation

### Requirements

- Python 3.10 or newer
- Internet access for initial dependency installation

The project has been tested with Python 3.12 and 3.13. The first run can create the environment and install the required packages automatically.

### Step 1: Open the Project Directory

```bash
cd econexus_ai
```

### Step 2: Configure API Keys (Optional)

```bash
cp .env.example .env
```

On Windows:

```powershell
copy .env.example .env
```

Open `.env` and add a Groq API key if you want to use the optional LLM mode of EcoNexus Copilot.

Obtain a key from:

https://console.groq.com

The platform works without this key using its built-in answer engine.

### Step 3: First-Run Setup

On the first execution of `python server.py`, `bootstrap.py`:

1. Checks the installed Python version.
2. Creates a private environment in `.venv/`, unless an active virtual or Conda environment is already being used.
3. Installs the packages listed in `requirements.txt`.
4. Checks whether the trained models in `artifacts/` can be loaded.
5. Retrains models if required (approximately four minutes).

Subsequent starts skip setup unless `requirements.txt` changes.

### Optional Manual Installation

```bash
python -m venv .venv
```

Activate the environment:

```bash
# macOS / Linux
source .venv/bin/activate

# Windows
.venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Methodology

### 1. Forecasting

A separate XGBoost model is used for each forecast-horizon and pollutant combination.

The system covers 18 horizons from 15 minutes to 72 hours for PM10 and PM2.5.

Models predict the log-change from the current concentration. Features use only information available at forecast time, and automated tests check for data leakage.

### 2. Uncertainty Estimation

Split-conformal prediction produces 90% intervals.

These are calibrated on a held-out window and evaluated on a later test window. Coverage is measured rather than assumed.

### 3. No-Action Baselines

Short-term forecasts (15–90 minutes) are trained without windows in which a new intervention started.

This supports the counterfactual question:

"What would happen if no action were taken?"

### 4. Validation

Evaluation uses:

- Hold-out testing.
- Four rolling-origin expanding-window cross-validation folds.
- Comparison against five baseline models.
- Time-based validation to prevent future-data leakage.

### 5. Explainability

Exact group-Shapley forecast drivers are calculated using five feature groups and all 32 coalitions, without a `shap` dependency.

An NNLS receptor model estimates source contributions and provides bootstrap ranges.

### 6. DUSTWISE Optimization

The Intervention Priority Score (IPS) is calculated as:

```text
IPS = 0.25 × Severity
    + 0.20 × Predicted Growth
    + 0.15 × Source Confidence
    + 0.15 × Exposure
    + 0.10 × Persistence
    + 0.15 × Feasibility
```

DUSTWISE compares actions using learned field multipliers and assigns fleet units using the Hungarian algorithm over Dijkstra routes on the site road network.

### 7. Bayesian Learning

A Bayesian field multiplier is maintained for each action, with prior distribution:

```text
N(1, 0.35²)
```

Each verified event updates the multiplier.

For the full technical description, see:

[METHODOLOGY_AND_EVALUATION.md](METHODOLOGY_AND_EVALUATION.md)

## Model Results

> **Important:** The results below were computed by `train.py` using the project's synthetic dataset. They are not evidence of performance on real construction-site data.

### Hold-Out Test

- Training period: Through 14 September
- Calibration period: 15–25 September
- Test period: 26 September–6 October
- Evaluation volume: Approximately 11,000–12,000 zone forecasts per horizon
- Pollutant: PM10, zone averages

| Forecast Horizon | RMSE (µg/m³) | MAE | R² | Skill vs. Persistence | 90% Interval Coverage | Exceedance Hit Rate (>150 µg/m³) |
|---|---:|---:|---:|---:|---:|---:|
| 15 min | 7.0 | 5.3 | 0.95 | +20% | 94% | 90% |
| 60 min | 9.1 | 6.8 | 0.92 | +29% | 94% | 77% |
| 90 min | 9.5 | 7.2 | 0.91 | +36% | 94% | 80% |
| 6 h | 16.2 | 12.2 | 0.74 | +48% | 93% | 74% |
| 24 h | 21.9 | 16.9 | 0.47 | +34% | 85% | 55% |
| 72 h | 28.4 | 21.7 | -0.03 | +42% | 82% | 35% |

The model performs most strongly at the operational forecast horizons used by DUSTWISE.

Beyond 24 hours, forecasts should be treated as an outlook because the 72-hour R² is close to zero and interval coverage is below the nominal 90%.

### Walk-Forward Benchmark

RMSE in µg/m³ across four expanding folds of ten days:

| Model | 60 min | 6 h | 24 h |
|---|---:|---:|---:|
| Persistence | 13.8 | 32.1 | 29.4 |
| Ridge | 8.8 | 14.6 | 16.2 |
| Random Forest | 7.3 | 11.9 | 15.9 |
| **XGBoost** | **7.0** | **11.8** | **15.4** |

### Additional Evaluation Results

- **Source Attribution:** Mean error of 6.2 percentage points against the simulator's true source shares.
- **Hero Event EV-042:** Zone B decreased from 199 to 152 µg/m³, an observed reduction of 23.4%.
- **Estimated Intervention Effect:** A 22.2% reduction relative to the no-action forecast, with a range of -29% to -15%. The event was marked as verified.

## EcoNexus Copilot

EcoNexus Copilot answers questions using platform data rather than inventing site values.

### Core Components

1. **Scope Filter:** Off-topic questions, such as general homework, jokes, or news, receive a brief decline before any LLM request is made.

2. **Built-in Answer Engine:** Questions are routed to one of 20 intents, including briefing, recommended actions, explanations, forecasts, priority, verification, sensors, model accuracy, weather, exposure, and fleet operations.

3. **Optional Groq LLM:** When `GROQ_API_KEY` is configured, Groq can rephrase and expand the built-in answer. It is constrained by a live context block containing verified platform values.

4. **Offline Operation:** Pre-computed answers are stored in `static/data/snapshot.js`, allowing the assistant to work without the server.

## Using Real Site Data

To use real telemetry, provide a long-format CSV containing these required columns:

```text
timestamp, zone_id, pm10, pm25, temperature, relative_humidity,
wind_speed, wind_dir_from
```

Optional columns include:

```text
mixing_height, rain_mm, reference_pm10, construction_intensity,
planned_construction, truck_trips, vehicles, intervention_active
```

Describe the site in `site_model.py`, then train the models using your CSV.

```bash
# macOS / Linux
.venv/bin/python train.py --data your_site.csv

# Windows
.venv\Scripts\python train.py --data your_site.csv
```

Real-world performance must be evaluated using representative, quality-controlled site data.

The synthetic-data results in this README should not be treated as real-site validation.

## Troubleshooting

| Symptom | Suggested Solution |
|---|---|
| `XGBoostError: input stream corrupted` | The model file may be damaged or incompatible. Run `python server.py --retrain`. |
| VS Code stops on an exception during setup | Run `python server.py` from a terminal or disable Raised Exceptions in debugger settings. |
| Project is inside OneDrive | Move it outside the synced folder, for example `C:\Projects\econexus_ai`. |
| Port 8000 is busy | The application selects another available port automatically. |
| Libraries fail to install | Check your internet connection, configure `HTTPS_PROXY` if required, use Python 3.10–3.13, and retry. |
| Google Maps is unavailable | Check Maps JavaScript API activation, billing, and website restrictions. |
| Map shows a plain site plan | Map tiles may be blocked or unavailable. Platform layers and interactions still work. |
| Page looks unstyled after an update | Hard-refresh the browser using Ctrl + F5. |

Models are saved in XGBoost's native model format rather than as pickled Python objects.

They are written atomically and recorded with SHA-256 checksums in `artifacts/manifest.json`. Damaged model files can therefore be detected and repaired through retraining.

## Known Limitations

- The current dataset is synthetic. Accuracy on a real construction site is unknown until the models are trained and evaluated using real telemetry.
- Forecasts from 24 to 72 hours are intended as an outlook. The 72-hour R² is close to zero and interval coverage is below 90%.
- The demo build exercises the EV-042 hero event through the API lifecycle.
- The built-in Copilot engine supports 20 known question types. More open-ended responses require the optional Groq API key.
- Voice input depends on browser support; Chrome and Edge are supported in the described build.
- Retraining may produce slightly different results with different library versions. The supplied model artifacts were trained using the versions pinned in `requirements.txt`.
